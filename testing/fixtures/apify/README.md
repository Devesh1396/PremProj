# Captured Apify dataset samples — `automation-lab/youtube-transcript`

Real output from real runs, kept so the K06 adapter is written against
**observed behaviour on both paths** rather than an assumed shape on either.
`testing/test_youtube.py` loads these; nothing in the adapter is shaped by a
guess about what the actor "probably" returns.

## `youtube_no_captions.json` — captured 2026-09-11

A video with **no transcript**. The reason this sample matters is that it is
not an error response: the run returns **HTTP 200 with a complete,
healthy-looking item** — real title, channel, description, view count,
duration, twenty-six keywords, thumbnail, publish date. Only these differ:

```
"segments": []              "segmentCount": 0
"language": ""              "selectedLanguage": ""
"availableLanguages": []    "isAutoGenerated": false
"error": "No transcript available for this video"
```

**`isAutoGenerated` is `false` here and that does NOT mean a human wrote
it.** It is false because there is no transcript at all. Read without first
confirming segments exist, a failed fetch records itself as the
highest-quality transcript type there is. `auto_generated_flag()` in
`scripts/youtube_apify.py` is the one place that field is read, and it
returns `None` when there are no segments.

VERBATIM from the capture: the five fields above, `viewCount` 9213178,
`durationSeconds` 515, and the twenty-six-keyword array's length.
PLACEHOLDER: `videoId`, `videoTitle`, `description`, `thumbnail`,
`publishDate` and the keyword strings — the capture's identity fields were
not recorded, and inventing plausible ones is honest where inventing a
plausible *shape* would not be. Nothing the adapter branches on is a
placeholder.

## The captions path

The transcript sample is constructed in `test_youtube.py` rather than stored
here, and is **shaped from** the 2026-09-10 live run rather than captured
byte for byte: the field list, the rolling-caption overlap (segment 1
0 → 2.16, segment 2 starting at 1.04), `isAutoGenerated: true`,
`segmentCount` 391 and the real `videoId`/`channelId` come from that run.
Said plainly because "shaped from a real run" and "captured verbatim" are
different claims and only one of them is true of that fixture.
