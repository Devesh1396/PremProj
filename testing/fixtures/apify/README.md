# Captured Apify dataset samples — `automation-lab/youtube-transcript`

Real output from real runs, kept so the K06 adapter is written against
**observed behaviour** rather than an assumed shape. `testing/test_youtube.py`
loads these. Each file's own `_fixture_note` records the actor run id, the
capture date, and exactly what was trimmed or removed.

| file | what it is |
|---|---|
| `youtube_transcript_ok.json` | a successful run. 20 keys, **no `error` key at all**, `isAutoGenerated` true, and consecutive segments whose starts precede the previous end — the rolling-caption overlap. |
| `youtube_transcript_absent.json` | the actor **reached** the video and it has no captions. Metadata is fully present; only the transcript fields are empty, plus `error`. |
| `youtube_transcript_read_failed.json` | the actor **never got there**. Every field blank, `error: "Failed to fetch transcript XML: HTTP 404"` — and a retry 63 seconds later returned 391 segments. |

## The distinction those last two files exist to force

`absent` and `read_failed` both have `segments: []`, and they mean opposite
things. One is a durable fact about the video; the other is a transient
failure that succeeded on retry a minute later. **Branching on empty
segments alone cannot tell them apart**, and treating a read failure as
"no transcript available" registers a perfectly good video as permanently
unreadable and never looks again.

`reached_video()` is the discriminator — the metadata is present in one and
blank in the other — and `actor_error()` carries the actor's own wording,
which is what makes the two distinguishable in the record afterwards.

An earlier revision of this adapter (superseded) had a single no-captions
fixture and branched on empty segments alone. It would have mis-filed the
`read_failed` case. That is the entire argument for capturing a real sample
of each state rather than one sample and a rule that sounds right.

## Still NOT captured

A **bad or removed video ID**. `read_failed` is a *transient* read failure
on a video that exists; a video that does not exist may produce a different
shape again, plausibly an empty dataset rather than an item. Nothing here
asserts what it looks like.
