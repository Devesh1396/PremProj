Companion to `first_source_loop.md`, which is a run report. This file is
the output itself: every claim, every concept proposal, every per-claim
decision and every strategy card, dumped from the database the
2026-09-11 run wrote. Nothing is selected and nothing is summarised.

Generated by SELECT, not written by hand. Where the database does not
hold something, it says so rather than filling the gap.

## What is stored, what is derived, and what is not recoverable

Read this before §3, because two of the verdicts asked for are NOT rows.

| | |
|---|---|
| Claims, concept proposals, strategies, evidence | **Stored.** Dumped verbatim below. |
| K10 triage verdict | **Not stored.** It is a pure function of `claims.claim_type` applied in `knowledge_research.queue()`: `RESEARCH_TYPES = ('SAFETY', 'INTERVENTION_EFFECT')`. `skipped_reason()` exists but is never written anywhere — `grep` finds only its definition. Derived below from the stored `claim_type`, and labelled as derived. |
| K10 `evidence_confidence` | **Not stored.** `apply_assessment()` returns it and `research_one()` prints it; there is no column for it on `claims`. The per-claim values printed at run time are in this session's log only. They are NOT reproduced here as if they were rows. |
| K11 four-way verdict | **Not stored as a word.** `synthesize_one()` reads `SYNTHESIS_JSON`, applies the decision and discards the token. What persists is the consequence: a `strategy_claims` link, a `DEPRECATED` status plus provenance note on a MERGE, and a `[K11: NO_CHANGE …]` marker appended to `claims.current_interpretation`. Derived from those below, with the evidence for each derivation shown. |
| Raw engine responses | **Not stored.** `engine_runs` has no response column, so the original `SYNTHESIS_JSON` and `EVIDENCE_JSON` are gone. |

That K10's verdict and K11's verdict leave no row is itself a finding:
both are decisions the system made about a claim, and neither is
auditable from the database alone.
